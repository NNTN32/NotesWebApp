# Backend working rules

- Java 21, Spring Boot **3.5.16**. App lives in `notesWeb/`; package ownership: [feature modules](notesWeb/docs/feature-modules.md).
- Preserve ownership/security checks, JWT/STOMP boundaries, RabbitMQ publisher confirms, transactional outbox/inbox, ACK/retry/DLQ and Redis Streams contracts. No Kafka.
- Tests: `node --test scripts/ci/*.test.mjs`; in `notesWeb/`, `bash ./mvnw -B test '-Dtest=!*IntegrationTest,!NotesWebApplicationTests'`. Integration/context tests require disposable PostgreSQL/Redis/RabbitMQ and CI fixture variables from `.github/workflows/CI.yml`; never use production `.env` or delete production volumes. Call the wrapper as `./mvnw` (plain `bash mvnw` cannot find `.mvn/wrapper`). If Maven Central is unreachable locally, say so in the PR and rely on CI.
- Release through a reviewed PR and green CI. Merge normally to release; put `[skip deploy]` in the **PR title** for CI/docs/test-only changes: GitHub copies the PR title into the merge commit message, and CI skips `publish`/`deploy` when that message contains it anywhere. Never write it in the title of a runtime change, not even negated. Branch from an up-to-date `main`, one topic per PR, and delete the head branch after merge. [CD runbook](notesWeb/docs/ci-cd.md) is authoritative: current merged main → immutable GHCR digest → CapRover app `server` on Lightsail Malaysia → served revision/readiness/public smoke + observation → latest promotion.
- Deployment target is fixed in `scripts/ci/deploy.mjs`; no OrbStack fallback and no mutable latest deployment. `CAPROVER_APP_TOKEN` (deploy-only token of app `server`) is a ProductBE secret only, main-only, rotated per [Credentials](notesWeb/docs/ci-cd.md#credentials); never commit tokens, environment exports or the CapRover admin password.
- Failed release remains failed after rollback. Preserve data/settings; CD rolls back only to the last digest promoted to `latest`. After a failed deploy check `/actuator/info` and the app's Deployment tab in CapRover before re-running. Keep rollback artifacts and encrypted off-VM backups.
- Production changes require user authorization and passed release gates. Do not upgrade AWS Free Plan or expose DB/queue/admin ports as a deployment shortcut.
